# 月別表示・再生の軽量化

ユーザー承認済み方針（2026-10-28）: 表示・再生の軽さを優先し、現行配信形式のまま格子形状の再利用、先読み・キャッシュ、表示を消さない切り替え、再生待ち時間の削減を行う。

## 選択した方法

- 現行の月別Float32/gzipとMapLibre/deck.glを維持して最適化する。約407 KiB/月の現行データでは、Zarr等への移行より描画更新と待ち時間の削減を先に評価する。
- Zarrによる空間分割やCDN移行は、計測で通信が依然として支配的な場合の候補とする。
- 格子座標を一定の配列として保持し、月変更時は高さ・色・欠測状態のみ更新する。地形標高の再評価はカメラ・DEM・地形設定・格子の変化に限定する。
- 月別データは容量上限付きLRUキャッシュに保持する。同じ月の取得を共有し、不要な通信は中止する。先読みは直近の観測月を少数ずつ行い、失敗しても現在表示を壊さない。
- 要求月と表示済み月を分け、表示月・値・チャートのカーソルを同時に確定する。欠測月は欠測のまま表示し、失敗時は直前の正常表示と読み込み先のエラーを示す。
- 再生では前の表示開始時刻から次の期限を計算する。読み込みが遅れた場合も月を飛ばさず、停止・速度変更・連続選択で古い結果を反映しない。

## 制約と検証

地球儀、3D柱、地形、Surface、地点選択、時系列、CSV、符号、不確実性、NaNを維持する。TypeScriptのany/unknown型と不要なclassは追加しない。新しいサービスや依存パッケージは追加しない。

キャッシュの上限・共有・中止・失敗後再試行、非同期競合、欠測、再生期限を自動検査する。実ブラウザーで同一条件の変更前後を比較し、形状生成回数、月切り替え時間、再生間隔、メモリー、描画・選択の正しさを記録する。ローカル実装と検証が対象で、公開デプロイは含めない。
